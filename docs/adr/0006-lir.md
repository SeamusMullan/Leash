# ADR-0006 LIR as a canonical JSON representation

Status: accepted.

## Context
Tooling, meta-agents and stable journal keys need a representation of programs
that does not depend on source formatting.

## Decision
A typed, desugared IR with stable node and site ids, serialisable to JSON
(`spec/lir.schema.json`), versioned. The interpreter runs LIR. `leash ir` dumps
it; `leash run --ir` consumes it.

## Alternatives
Interpret the AST directly (simplest; but ids drift with formatting and every
tool needs the parser); a bytecode VM (premature).

## Consequences
- One extra lowering pass to maintain.
- Site ids must be defined precisely (module, item, structural path) and tested
  for stability under formatting and comment changes.
